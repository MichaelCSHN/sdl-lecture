# SDL Course App PRD

版本：3.0  
日期：2026-06-04  
状态：active

## 1. 产品定义

围绕 Self-driving Labs 与 A-Lab，构建一套面向研究生与高年级本科生的数字课程平台。

它首先是一门完整课程，其次支持一条 3 小时研究生讲座压缩路径。

当前项目策略：

1. `North Star` 是完整课程。
2. `Immediate Milestone` 是讲座版 MVP。

## 2. 目标用户

1. 材料、化学、实验科学相关方向研究生。
2. 具备一定基础的高年级本科生。
3. 想快速理解 SDL 工作流的科研人员。
4. 讲者、课程助教和实验室内部培训人员。

## 3. 课程定位

### 完整课程模式

目标是“可持续学习、可复盘、可扩展”。

必须满足：

1. 章节与学习路径。
2. 课程目录与检查点。
3. 可持续扩展的案例体系。
4. 研究设计工作室。
5. 资源、作业和后续阅读体系。

### 讲座压缩模式

目标是“讲清楚、演得稳、讲完能回看”。

必须满足：

1. 一条完整讲座叙事线。
2. 一页高质量 A-Lab 档案。
3. 至少 2 个课堂可演示案例。
4. 现场不依赖外部 API 成功返回。
5. 讲后可供学生独立浏览。

### 当前优先交付范围：Lecture MVP

讲座 deadline 下，必须优先交付：

1. 新首页与课程入口
2. Foundations 的前半核心内容
3. A-Lab 深度案例页
4. 至少 1 个稳定可演示 benchmark case
5. 至少 1 个研究生层级可讲的反应或材料 case
6. 讲者模式最小能力

## 4. 成功标准

### 讲座压缩模式验收

1. 讲者可在 3 小时内完成完整演示，不需要大量离线补充说明。
2. 学生能解释 SDL 闭环中的参数、观测、推荐和验证分别是什么。
3. 学生能复述至少 1 个案例为何推荐下一个实验点。
4. A-Lab 页面可独立阅读，不像营销页或时间线拼贴。

### 完整课程模式验收

1. 用户能按课程顺序完成学习，而不是只做页面浏览。
2. 至少 3 个案例达到研究生课程可讲标准。
3. Methods Lab 与 Case Studio 明显分工，不混杂。
4. Research Design Studio 输出结构化建议，而不是闲聊文本。

## 5. 核心产品模块

1. 首页：课程入口，不是讲座海报。
2. Course：课程总览、路径和预期学习收益。
3. Foundations：背景知识、实验史、MSE 实验图谱、DOE 与 SDL 基础。
4. A-Lab Case File：深度案例档案。
5. Case Studio：案例工作台。
6. Methods Lab：DOE / BO / 多目标优化方法教学。
7. Research Design Studio：把研究问题结构化为 SDL 设计任务。
8. Resources：阅读和工具体系。

## 6. 关键用户场景

### 讲者场景

1. 讲者按课程路径推进。
2. 讲者在需要时切换到案例工作台演示。
3. 讲者可快速 reset 或 replay 关键案例。

### 学生场景

1. 学生在课前或课后浏览课程内容。
2. 学生先通过 Foundations 建立对实验的全局认识。
3. 学生进入 A-Lab 档案理解真实系统。
4. 学生用 Case Studio 观察闭环推荐如何产生。

### 研究启发场景

1. 用户输入自己的课题方向。
2. 系统输出参数、约束、可测指标和适用策略草案。

## 7. 内容质量标准

1. 不允许只有名词解释，没有实验语义。
2. 不允许把 toy surrogate 伪装成多个不同科研案例。
3. 不允许把“图表多”误当成“内容深”。
4. 任何关键结论都应能回答：
   - 变量是什么
   - 观测是什么
   - 推荐依据是什么
   - 失败边界是什么

## 8. 案例标准

### P0 必做案例

1. RGB LED / 颜色匹配 benchmark
2. 一个反应优化案例：`SnAr` 或 `Suzuki`
3. 一个材料类实验案例

### P1 优先候选

1. 材料配方或工艺优化案例
2. 多目标绿色化学案例

### 案例统一要求

每个案例都必须有：

1. 背景任务
2. 参数空间
3. 观测输出
4. 目标与约束
5. 推荐理由
6. 历史记录
7. replay / seed

## 9. 产品原则

1. 课程优先于页面拼贴。
2. 实验优先于算法炫技。
3. 观测优先于抽象得分。
4. 案例优先于概念堆砌。
5. 可复盘优先于炫技动效。
6. 稳定可讲优先于过度追求实时 AI。

## 9.1 顶层课程立场

### 拥抱 AI

本课程主动使用 AI 来增强知识组织、专题研究、软件开发、案例实现和研究复盘能力。

课程必须体现：

1. AI 参与知识框架构建与知识更新。
2. AI 参与研究任务拆解与问题求解。
3. AI 参与软件、数据和原型开发。

### 质疑 AI

本课程同时坚持人的判断、反馈和伦理责任。

课程必须体现：

1. 人类直觉、领域知识和实践技能不可被弱化。
2. 人必须在关键目标设定、结果解释和验证中承担责任。
3. 平台必须支持对 AI 建议进行质疑、审查和复盘。
4. 科学伦理、透明度和可重复性不得让位于效率崇拜。

## 10. 当前项目处理原则

1. 旧代码可以复用，但不保留旧信息架构。
2. 旧单页结构不再作为新产品基础。
3. 如果旧代码妨碍重构，允许 Claude 直接删改。
