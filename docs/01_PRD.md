---

## 1. 产品定义

围绕 Self-driving Labs 与 A-Lab，构建一套面向研究生与高年级本科生的数字课程平台。

它首先是一门完整课程，其次支持一条 3 小时研究生讲座压缩路径。

当前项目策略：

1. `North Star` 是完整课程。
2. `Immediate Milestone` 是讲座版 MVP。

---

## 2. 目标用户

1. 材料、化学、实验科学相关方向研究生。
2. 具备一定基础的高年级本科生。
3. 想快速理解 SDL 工作流的科研人员。
4. 讲者、课程助教和实验室内部培训人员。

---

## 3. 课程定位

### 3.1 完整课程模式

目标是"可持续学习、可复盘、可扩展"。

必须满足：

1. 章节与学习路径。
2. 课程目录与检查点。
3. 可持续扩展的案例体系。
4. 研究设计工作室。
5. 资源、作业和后续阅读体系。

### 3.2 讲座压缩模式

目标是"讲清楚、演得稳、讲完能回看"。

必须满足：

1. 一条完整讲座叙事线。
2. 一页高质量 A-Lab 档案。
3. 至少 2 个课堂可演示案例。
4. 现场不依赖外部 API 成功返回。
5. 讲后可供学生独立浏览。

### 3.3 当前优先交付范围：Lecture MVP

讲座 deadline 下，必须优先交付：

1. 新首页与课程入口。
2. Foundations 的前半核心内容。
3. A-Lab 深度案例页。
4. 至少 1 个稳定可演示 benchmark case（RGB LED）。
5. 至少 1 个研究生层级可讲的反应或材料 case（SnAr 或薄膜沉积）。
6. 讲者模式最小能力。

**✦ v4.0 明确：Design Studio 不在 Lecture MVP 范围内，Phase B 实现。**

### 3.4 ✦ v4.0 新增：离线优先约束

Lecture MVP 阶段，所有在讲座现场使用的功能必须满足：

1. Case Studio 的 P0 案例数据完全内置于代码仓库，不依赖任何外部 API 或数据库。
2. Foundations 的两个交互说明块完全在浏览器内运行。
3. A-Lab 页面为纯静态内容，不依赖外部数据源。
4. 任何实时 AI 功能（如 Design Studio 的 AI 建议生成）都是 Phase B 可选增强，不得影响 MVP 的稳定性。

## 4. 成功标准

### 4.1 讲座压缩模式验收

1. 讲者可在 3 小时内完成完整演示，不需要大量离线补充说明。
2. 学生能解释 SDL 闭环中的参数、观测、推荐和验证分别是什么。
3. 学生能复述至少 1 个案例为何推荐下一个实验点（不只是"acquisition 函数大"，要能说出具体理由）。
4. A-Lab 页面可独立阅读，不像营销页或时间线拼贴。

### 4.2 完整课程模式验收

1. 用户能按课程顺序完成学习，而不是只做页面浏览。
2. 至少 3 个案例达到研究生课程可讲标准。
3. Methods Lab 与 Case Studio 明显分工，不混杂。
4. Research Design Studio 输出结构化建议，而不是闲聊文本。

### ✦ v4.0 新增 4.3：可量化验收标准

以下标准必须在验收时逐项 check：

**Case Studio 验收**：
- [ ] 点击推荐点后，"推荐理由"区域显示包含参数值、不确定度估计和推荐逻辑的完整解释（>40 字）
- [ ] P0 三个案例均可在无网络情况下运行完整闭环（reset → 推荐 → 步进 → 更新）
- [ ] 每个案例在 reset 后，前 3 步实验点来自 seed_experiments，不随机变化

**Foundations 验收**：
- [ ] 交互块 1（SDL 闭环步进）可在无 API 情况下完成 5 步演示
- [ ] 交互块 2（Acquisition 探索器）拖动 β 滑块后，推荐点坐标确实发生变化
- [ ] MSE 实验图谱以视觉化方式呈现（不是纯文字表格）

**A-Lab 验收**：
- [ ] 页面包含至少 3 个来自原始论文的定量数据点（带来源引用）
- [ ] "争议与再分析"部分字数不少于 300 字
- [ ] 页面没有出现以下内容：纯时间线、股票图片、功能徽章

**讲者模式验收**：
- [ ] 激活讲者模式后顶部出现可见的进度指示器
- [ ] 键盘 `→` 可推进到下一讲座节点
- [ ] 在 Case Studio 内键盘 `R` 可重置案例状态
- [ ] 讲者工具栏的存在不影响学生的正常浏览体验

## 5. 核心产品模块

1. 首页：课程入口，不是讲座海报。
2. Course：课程总览、路径和预期学习收益。
3. Foundations：背景知识、实验史、MSE 实验图谱、DOE 与 SDL 基础。
4. A-Lab Case File：深度案例档案。
5. Case Studio：案例工作台。
6. Methods Lab：DOE / BO / 多目标优化方法教学。
7. Research Design Studio：把研究问题结构化为 SDL 设计任务（Phase B）。
8. Resources：阅读和工具体系。

### ✦ v4.0 新增 5.1：各模块内容深度要求

**Foundations** 必须包含以下内容层次，不能压缩为名词清单：

- 实验的哲学地位：观察 vs. 干预，什么是"受控"（用 Claude Bernard 的历史案例锚定）
- MSE 实验图谱：按"研究范式 × 尺度"二维矩阵组织，覆盖狭义实验、计算模拟、高通量、数据驱动四类
- 方法演化叙事：OFAT → 全因子设计 → RSM → Bayesian Optimization → SDL，每一步演化都用一个具体失败案例解释"为什么前一步不够"
- surrogate-uncertainty-acquisition 三角：必须有图示说明三者的关系，不能只是文字定义

**A-Lab** 必须包含来自 Szymanski et al. (2023) *Science* 的定量信息：
- 实验迭代次数与传统方法的对比
- 合成成功率与验证成功率（两个数字分开说明）
- 人类判断在整个流程中的具体位置（哪些步骤仍然需要人工介入）

**Case Studio** 每个案例必须包含：
- 真实或合理的参数范围（带物理/化学意义的单位）
- 至少 5 个 seed 实验点（确保讲座演示从非空历史开始）
- "推荐理由"的模板化文字（见 §6.1 对应规格）

## 6. 关键用户场景

### 6.1 ✦ v4.0 扩展：讲者模式完整操作规格

**进入讲者模式**：
- URL 参数 `?mode=lecture` 激活，或首页"讲者入口"按钮激活
- 激活后顶部导航栏添加琥珀色工具栏（不替换原导航，而是在其上方追加一行）

**讲者工具栏包含**：
- 当前讲座节点名称（如"Foundations / SDL 闭环概念"）
- 进度指示（如"节点 4/12"）
- `←` 上一节点 / `→` 下一节点 按钮
- `Reset` 按钮（当前页面是 Case Studio 时激活，重置到 seed 状态）
- `Replay` 按钮（当前页面是 Case Studio 时激活，逐步回放历史实验记录）
- `Exit` 按钮（退出讲者模式，返回学生视图）

**键盘快捷键**（讲者模式下全局有效）：
- `→` / `Space`：进入下一讲座节点
- `←`：返回上一讲座节点
- `R`：Reset 当前 Case Studio 状态
- `P`：Replay（从第 1 步开始逐步播放实验历史）
- `F`：全屏当前内容区域（排除工具栏）
- `L`：切换讲者/学生视图

**讲座节点定义**（Lecture MVP 阶段的完整序列）：

| 节点编号 | 页面 | 节点名称 |
|---|---|---|
| 1 | `/` | 课程介绍与学习目标 |
| 2 | `/foundations` | 实验的本质与地位 |
| 3 | `/foundations` | MSE 实验图谱 |
| 4 | `/foundations` | 从 OFAT 到 DOE 到 SDL |
| 5 | `/foundations` | SDL 闭环步进演示 |
| 6 | `/foundations` | surrogate-uncertainty-acquisition |
| 7 | `/foundations` | Acquisition Function 探索器 |
| 8 | `/a-lab` | A-Lab 问题定义与系统组成 |
| 9 | `/a-lab` | 执行闭环与关键结果 |
| 10 | `/a-lab` | 争议与再分析 |
| 11 | `/case-studio` | RGB LED Benchmark 演示 |
| 12 | `/case-studio` | 薄膜沉积材料案例 |

### 6.2 学生场景

1. 学生在课前或课后浏览课程内容。
2. 学生先通过 Foundations 建立对实验的全局认识。
3. 学生进入 A-Lab 档案理解真实系统。
4. 学生用 Case Studio 观察闭环推荐如何产生。

### 6.3 研究启发场景（Phase B）

1. 用户输入自己的课题方向。
2. 系统输出参数、约束、可测指标和适用策略草案（离线模板优先）。

## 7. 内容质量标准

1. 不允许只有名词解释，没有实验语义。
2. 不允许把 toy surrogate 伪装成多个不同科研案例。
3. 不允许把"图表多"误当成"内容深"。
4. 任何关键结论都应能回答：
   - 变量是什么
   - 观测是什么
   - 推荐依据是什么
   - 失败边界是什么

### ✦ v4.0 新增 7.1：可验证的内容质量标准

以下是从"定性原则"转化为"可 check 的约束"：

| 禁止模式 | 可验证标准 |
|---|---|
| toy surrogate 伪装案例 | 每个案例的参数来自真实文献或可解释的物理/化学背景，需注明来源 |
| 只有名词解释 | 每个概念的引入必须伴随至少一个具体实验例子（参数、观测、结论） |
| 图表多 ≠ 内容深 | 每张图表下方必须有至少 2 句文字说明"这张图说明了什么" |
| 营销文案 | 禁止使用"革命性"、"前所未有"、"颠覆性"等词汇；所有定量主张必须有来源 |

## 8. 案例标准

### 8.1 P0 必做案例

**案例 1：RGB LED / 颜色匹配 benchmark**
- 参数：R（0–255）、G（0–255）、B（0–255）
- 观测：色差 ΔE（与目标颜色的欧氏距离，越小越好）
- 目标：最小化 ΔE，找到与目标颜色最接近的 RGB 组合
- 数据来源：内置合成数据（基于标准色觉模型），seed 实验 5 个
- 特点：参数直觉最强，适合作为第一个演示案例

**案例 2：反应优化（SnAr 或 Suzuki）**
- 参数：反应温度（°C）、反应时间（min）、溶剂比例（%）、底物摩尔当量
- 观测：产率（%）
- 目标：最大化产率
- 数据来源：参考 Reizman & Jensen (2016) 的 SnAr 数据集，内置预处理版本
- 特点：化学领域学生熟悉，失败模式丰富（副反应、溶解性问题）

### ✦ v4.0 新增 8.2：P0 材料类案例：薄膜沉积参数优化

**案例 3：薄膜沉积参数优化**
- 背景：在基底上通过 CVD/PVD 制备功能薄膜，需要优化制备参数以获得最高薄膜均匀性
- 参数：
  - 沉积温度 T：300–600°C（步长 10°C）
  - 工作气压 P：0.1–10 Pa（对数刻度）
  - 前驱体流量 F：10–100 sccm（步长 5 sccm）
- 观测：薄膜均匀性 U（1–100%，越高越好）；辅助观测：表面粗糙度 Ra（nm，越低越好）
- 目标：最大化 U，约束 Ra < 5 nm
- 失败边界：
  - T > 560°C：薄膜开始脱落，U 骤降至 < 20%
  - P < 0.5 Pa：表面粗糙度 Ra > 8 nm，超出约束
  - F < 15 sccm 且 T < 350°C：沉积速率过低，实验失败
- 数据来源：内置合成数据，基于简化 Gaussian Process 模型，物理参数参考 PECVD 文献范围
- Seed 实验：5 个初始点，覆盖参数空间对角线（低-低-低 / 高-高-高 各一个，其余 3 个随机）
- 数据文件：`src/data/thin-film-case.json`（格式见 Spec v2.0 §6）

### 8.3 P1 优先候选

1. 材料配方或工艺优化案例
2. 多目标绿色化学案例

### 8.4 案例统一要求

每个案例都必须有：

1. 背景任务
2. 参数空间（含单位和物理意义）
3. 观测输出（含单位和目标方向）
4. 目标与约束
5. 推荐理由（固定模板格式，见 Spec v2.0 §2.5）
6. 历史记录（含 seed 实验，确保讲座从非空状态演示）
7. reset / replay 功能

## 9. 产品原则

1. 课程优先于页面拼贴。
2. 实验优先于算法炫技。
3. 观测优先于抽象得分。
4. 案例优先于概念堆砌。
5. 可复盘优先于炫技动效。
6. 稳定可讲优先于过度追求实时 AI。

### 9.1 顶层课程立场

**拥抱 AI**：本课程主动使用 AI 来增强知识组织、专题研究、软件开发、案例实现和研究复盘能力。

课程必须体现：

1. AI 参与知识框架构建与知识更新。
2. AI 参与研究任务拆解与问题求解。
3. AI 参与软件、数据和原型开发。

**质疑 AI**：本课程同时坚持人的判断、反馈和伦理责任。

课程必须体现：

1. 人类直觉、领域知识和实践技能不可被弱化。
2. 人必须在关键目标设定、结果解释和验证中承担责任。
3. 平台必须支持对 AI 建议进行质疑、审查和复盘。
4. 科学伦理、透明度和可重复性不得让位于效率崇拜。

### ✦ v4.0 新增 9.2：美学与视觉设计原则

1. **科学参考文献，不是产品营销页**：视觉语言参照 Distill.pub、学术期刊排版，不参照 SaaS 落地页。
2. **排版优先，图表其次**：正文文字是第一位的内容载体，图表是辅助理解的工具，不是装饰。
3. **数据颜色语义全站统一**：已探索=灰、推荐=蓝、最优=绿、不确定性=琥珀，任何图表不得违反这个约定。
4. **可量化才可展示**：所有图表的轴标签必须带单位，所有数字必须有来源或说明。
5. **禁止以下元素**：股票图片、渐变背景、动画计数器、功能徽章、营销词汇、以 Modal 弹窗承载核心内容。
6. **讲者模式有明确的视觉标识**：激活讲者模式时顶部显示琥珀色工具栏，与学生视图有清晰的视觉区分。
