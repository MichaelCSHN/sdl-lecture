## 1. 信息架构

本产品按"完整课程平台"设计，讲座版由课程路径裁切生成。

当前交付优先级：

1. 先让讲座版 MVP 可用。
2. 实现方式必须直接服务完整课程结构。

### 一级路由

```
/               首页·课程入口
/course         课程总览
/foundations    基础知识
/a-lab          A-Lab 案例档案
/case-studio    案例工作台
/methods        方法教学
/design-studio  研究设计工作室（Phase B）
/resources      资源体系
```

所有路由使用 `HashRouter`（`#/xxx`），以兼容 GitHub Pages 静态部署，不需要服务端路由配置。

### 共用壳层

1. 顶部全局导航：logo + 路由导航链接 + 讲者模式开关
2. 桌面端课程侧栏：当前页面的章节目录（可折叠）
3. 移动端折叠菜单
4. 页脚：当前页面的关键术语快速索引（可选）

## 2. 页面规格

每个页面遵循统一的四层结构：

```
定向层（Context）   → 告诉用户"这一页在整个课程里的位置"，轻量（1–2 行）
核心内容层（Content）→ 这一页的实质内容，可以是长文本、图表、对比表
行动层（Action）    → 可操作的交互块、演示、工具
衔接层（Bridge）    → 指向下一个学习步骤
```

### 2.1 首页 `/`

**目标**：作为课程入口页。风格是高质量学术课程介绍，不是讲座海报。

**定向层**：无（首页不需要定向层）

**核心内容层**：

- 一句话核心定义（≤25 字）：准确描述这门课程教什么，不使用"革命性"等营销词汇
- 适合人群说明：简洁列出三类目标用户（研究生 / 高年级本科生 / 想快速入门的科研人员）
- 两阶段目标说明：
  - Phase A（讲座版）：3 小时内建立 SDL 闭环直觉，能讲清楚一个完整案例
  - Phase B（完整课程）：系统掌握从实验设计到 SDL 的方法论体系

**行动层**：三个主入口，等权重，视觉清晰区分：

- 「开始课程」→ `/course`（学生默认入口）
- 「进入案例工作台」→ `/case-studio`（直接跳到演示）
- 「查看 A-Lab 档案」→ `/a-lab`（直接进入核心案例）

**衔接层**：无（首页不需要）

**严格禁止**：

- 带股票图片或机器人照片的 Hero 横幅
- 功能徽章或营销词汇
- 列举数字（"已有 X 位学生"类）

### 2.2 Course `/course`

**目标**：让用户在 5 分钟内理解整个课程的结构和学习路径。

**定向层**：一句话定位（"这是整门课程的地图"）

**核心内容层**：

- 课程地图（视觉化，不是纯文字列表）：展示 8 个模块及其推荐阅读顺序，以有向图或带箭头的卡片组呈现
- 每个模块的章节卡片，包含：模块名称、一句话目标、预计学习时间、是否纳入讲座 MVP（标注"讲座必看" / "完整课程"）
- 完整课程与讲座压缩版的区别说明：以并排对比展示（不是段落描述）

**行动层**：

- 「开始学习」按钮（指向 `/foundations`）
- 「进入讲者模式」按钮（激活讲者模式后自动从节点 1 开始，仅对已标记讲者的用户显示，或通过 `?mode=lecture` URL 参数触发）

**衔接层**：指向 `/foundations`

### 2.3 Foundations `/foundations`

**目标**：建立实验中心视角、MSE 实验分类认知，以及 SDL 方法与闭环直觉。

**内容逻辑顺序**（必须按此顺序排列，不得跳过或合并）：

1. 实验的本质与地位
2. MSE 实验图谱
3. 从 OFAT 到 SDL 的演化
4. SDL 闭环核心概念
5. 关键方法直觉

**§ 实验的本质与地位**

内容要点：
- 区分观察（observation）与干预（intervention）：实验是主动干预，不是被动记录
- 实验的逻辑结构：假设 → 自变量/控制变量/因变量 → 对照 → 重复 → 推断
- 为什么实验在材料科学中尤其关键：材料的性质由制备历史决定，无法从第一性原理推导全部

用历史案例锚定：James Lind（1747）的坏血病实验作为"第一次临床受控试验"，说明"控制变量"思想的力量。不需要展开历史叙事，两段文字即可。

**§ MSE 实验图谱**

展示形式：**必须是视觉化矩阵**，不接受纯文字表格。

矩阵维度：
- 行（Y 轴）：研究范式，从上到下：第一范式（经验/实验室）→ 第二范式（理论驱动）→ 第三范式（计算模拟）→ 第四范式（数据驱动）
- 列（X 轴）：尺度维度，从左到右：量子/电子（Å）→ 原子（nm）→ 微观（μm）→ 介观/宏观（mm–m）

每个矩阵格内：2–3 个代表性技术名词（如"HRTEM / APT"在原子 × 实验室格）

矩阵右侧或下方：SDL 以带颜色的覆盖层标注"横跨多范式、聚焦宏观→微观闭环"

**§ 从 OFAT 到 SDL 的演化**

内容组织：4 步线性叙事，每步包含"方法名称 → 解决了什么问题 → 遗留了什么问题"三段：

1. **OFAT（一次一因素）**：直觉最简单，但遗漏因素交互效应，效率低
2. **全因子设计 → RSM（响应面）**：Fisher 的贡献，系统覆盖参数空间，但实验次数随维度指数增长
3. **Bayesian Optimization**：自适应采样，将先验知识和已有观测结合，减少"浪费"的实验
4. **SDL**：将 BO 与实验自动化结合，实现无人干预的闭环迭代

每步用 1 个具体的材料科学例子（参数、观测值范围）说明"这一步在实际中是什么感觉"。

**§ SDL 闭环核心概念**

内容要点：
- SDL 闭环的五个阶段（图示，必须有）：提出候选点 → 执行实验 → 获得观测 → 更新 surrogate → 提出新候选点
- Surrogate Model：用已有实验点拟合的"代理函数"，预测未探索区域的输出；输出不只是预测值，还有不确定度
- Acquisition Function：在"哪里探索"上做决策的函数，平衡高预测值区域（exploitation）和高不确定性区域（exploration）

**行动层：交互块 1 — SDL 闭环步进演示**

规格：
- 初始状态：空参数空间（2D，双轴为两个连续参数），仅显示 seed 实验点（灰色散点）
- 每次点击"下一步"：添加推荐点（高亮蓝色散点），后端（浏览器内）更新 surrogate 可视化（等高线或颜色热图），文字区域同步更新"当前阶段说明"
- 共 5 步（可配置）
- 完成后显示"replay" 按钮
- 技术约束：完全在浏览器内运行，不调用任何外部 API；使用预计算的 surrogate 数据或简单的 RBF 插值

文字说明格式（每步固定模板）：
```
第 [N] 步：[阶段名称]
[1–2 句描述当前发生了什么]
[推荐下一步实验的理由（1 句）]
```

**§ 关键方法直觉**

内容要点：
- Exploration vs. Exploitation 的权衡：为什么不能只做"看起来最好"的实验
- Uncertainty 的语义：不确定性高 ≠ 这里可能很好，而是"这里信息少，探索有价值"
- 为什么随机采样不如 BO：通过一个简单的数字例子说明（在 10×10 网格上，随机搜索 vs BO 分别需要多少次找到最优点）

**行动层：交互块 2 — Acquisition Function 探索器**

规格：
- 显示内容：1D 参数空间，三条曲线叠加：
  1. Surrogate posterior 均值（实线）
  2. Surrogate 置信带（半透明填充）
  3. Acquisition function 曲线（另一种颜色，在独立 Y 轴上）
  4. 推荐点（最大 acquisition 值处，竖虚线标注）
- 交互：β 滑块（UCB 的 exploration weight）。拖动后实时更新 acquisition function 曲线和推荐点位置
- 技术约束：使用固定的 surrogate posterior（预计算），只有 acquisition function 随 β 变化
- 必须有说明文字解释 β 的物理含义："β 越大 → 更倾向探索不确定区域；β 越小 → 更倾向利用当前最优预测"

**衔接层**：「完成本章后，进入 A-Lab 查看真实系统的完整闭环」→ `/a-lab`

### 2.4 A-Lab `/a-lab`

**目标**：把 A-Lab 做成深度案例档案，风格是"详尽的研究案例报告"，不是展板或时间线。

页面结构（必须按此顺序）：

**§ 问题定义**

- 研究问题（一句话）：A-Lab 要解决什么科学问题？
- 目标函数：优化什么属性？约束是什么？
- 参数空间：搜索的变量是什么？维度？

**§ 系统组成**

展示形式：系统架构图（不是图标列表），展示四个模块之间的数据流：
- 合成模块（机器人化学合成）
- 表征模块（XRD、光学测量等）
- 数据处理模块（结果提取与格式化）
- 推荐模块（BO/AI 推荐下一个实验）

每个模块下附：2–3 个关键技术参数（如"合成通量：X 个配方/天"）

**§ 执行闭环**

内容：以数字化时序展示真实实验记录的关键节点（不是装饰性时间线，而是附有定量数据的过程记录）

必须包含的定量信息（来源：Szymanski et al. 2023 *Science* 及关联论文）：
- 总实验迭代次数
- 实验周期（每次迭代的平均时间）
- 与随机搜索/网格搜索的效率对比（倍数或所需实验次数对比）
- 合成成功率（某批次样品实际被成功合成的比例）

**§ 关键结果**

内容：以 Pull Quote 格式突出 2–3 个最重要的定量结论。格式示例：
```
「在 [X] 次实验后，A-Lab 识别出 [Y] 种符合目标性能的材料配方，
  而随机搜索需要 [N×X] 次才能达到同等覆盖。」
                               — Szymanski et al., Science 2023
```

**§ 争议与再分析**（最重要，必须占据显著篇幅，不得少于 300 字）

以"辩论格式"组织：

正方（支持 A-Lab 的 SDL 方向）：
- 证据 1：效率提升的定量数据
- 证据 2：系统发现了人类不直觉的材料配方

反方（质疑或局限性）：
- 质疑 1：合成 → 表征的闭环是否真正"自主"？哪些步骤仍需人工判断？
- 质疑 2：搜索的参数空间是否代表真实材料设计空间，还是预先筛选过的子空间？
- 质疑 3：在有限的目标函数定义下，"成功"的标准是否过于简化？

综合判断：
- 1–2 段综合分析，不站在单方面

**§ 对学生的真实启示**

内容：3–5 条具体的、可操作的学习建议，格式示例：
- "当你设计自己的 SDL 实验时，首先要问的不是'用什么算法'，而是'我的观测量是否真的衡量了我关心的属性'"
- "A-Lab 的成功很大程度上依赖于高通量合成与表征的硬件自动化，这是大多数实验室的瓶颈，不是算法瓶颈"

**衔接层**：「亲自运行一个简化版闭环」→ `/case-studio`

### 2.5 Case Studio `/case-studio`

**目标**：让学生亲眼看到 SDL 如何选下一个实验，理解推荐背后的逻辑，不只是"按下按钮看结果"。

**整体布局**（桌面端两栏，移动端单栏）：
- 左栏（40%）：控制区（案例选择、参数显示、推荐理由、历史记录）
- 右栏（60%）：可视化区（散点图 + 等高线/surrogate 可视化）

**控制区规格**：

1. **案例选择器**：下拉菜单或标签页，包含 P0 三个案例：RGB LED / SnAr 反应 / 薄膜沉积。切换案例时重置所有状态。

2. **参数与约束区**：
   - 展示当前案例的所有参数名、单位、范围（只读，不提供手动输入）
   - 展示优化目标（如"最大化均匀性 U"）和约束（如"Ra < 5 nm"）
   - 若当前推荐点触碰约束边界，显示警告提示

3. **推荐点与推荐理由**：
   
   推荐点：以参数格式显示（如"T = 420°C, P = 2.3 Pa, F = 55 sccm"）
   
   推荐理由（固定模板，由前端根据数据填充，不调用 AI）：
   ```
   当前已完成 [N] 次实验。模型在 [参数名A] = [值] 、[参数名B] = [值] 处的
   预测不确定性最高（标准差 σ = [值]）。

   按当前策略（[策略名称]），探索高不确定性区域的预期信息增益最大。

   模型预测该点的 [目标变量] ≈ [μ] ± [σ]（[置信水平]% 置信区间）。
   当前历史最优值为 [最优值]，出现在第 [K] 次实验。
   ```

4. **历史记录表**：
   - 列：实验编号、各参数值（含单位）、观测输出（含单位）、是否为 best-so-far（✓ 标注）
   - 行高固定，超过 8 行后可纵向滚动（历史表本身）
   - 最新一次实验高亮显示
   - 表格使用等宽字体显示数值

5. **reset / replay 控件**（讲者模式下显示，学生模式下也可见）：
   - `Reset`：清除所有历史，恢复到 seed 状态（seed 实验点保留，不清除）
   - `Replay`：从第 1 步开始逐步播放，每次点击"下一步"推进一个实验

**可视化区规格**：

1. **散点图**（主要图表）：
   - X 轴、Y 轴：当前选定的两个参数（如果参数超过 2 个，提供轴选择器）
   - 点颜色编码（严格遵循视觉设计规范）：
     - 已探索点：灰色（`#9B9B9B`）
     - 当前推荐点：蓝色（`#2B6CB0`），标注"→ 推荐"
     - 历史最优点：绿色（`#276749`），标注"★ 最优"
   - Hover 提示：精确参数值 + 观测值 + 不确定度
   - 轴标签：参数名 + 单位（必须有）

2. **Surrogate 可视化**（等高线图或颜色热图，叠加在散点图上）：
   - 颜色表示预测均值（暖色 = 高值，冷色 = 低值）
   - 半透明，不遮挡散点
   - 颜色条（colorbar）带最小值和最大值标注

**讲者模式下的额外控件**：

- 步进控件："← 上一步" / "下一步 →"（逐步执行推荐实验）
- 快进控件："快进到第 N 步"（跳转到指定步骤数）
- 当前最优点的视觉标注（放大显示）

### 2.6 Methods `/methods`

**目标**：方法教学，与 Case Studio 明确分工——Methods 讲"是什么和为什么"，Case Studio 演示"怎么跑"。Methods 不包含可运行的案例演示。

**内容组织**（4 个独立子节，每个子节可单独访问）：

**§ DOE 方法对比**

以对比表格展示（表格必须有列：方法名、适用场景、优点、局限、典型实验次数 vs 因素数）：

| 方法 | 适用场景 | 优点 | 局限 |
|---|---|---|---|
| OFAT | 单因素筛查 | 直觉简单 | 遗漏交互效应 |
| 全因子设计 | 因素数 ≤ 4 | 完整信息 | 实验次数指数增长 |
| 分式析因设计 | 因素数 5–15，筛选阶段 | 高效 | 混淆高阶交互 |
| RSM（响应面） | 优化阶段，已知关键因素 | 拟合曲面，找最优 | 仅适用于连续响应 |
| Bayesian Optimization | 昂贵实验，高维参数 | 自适应，样本效率高 | 需要 surrogate 质量高 |

每种方法下附一个具体例子（参数数量和实验次数的具体数字）。

**§ BO Acquisition Function 对比**

以对比表格展示（含数学形式的简写，不需要完整推导）：

| Acquisition Function | 倾向性 | 适用场景 | 参数 |
|---|---|---|---|
| UCB（Upper Confidence Bound） | 可调 exploitation/exploration | 通用 | β（越大越 explore） |
| EI（Expected Improvement） | 偏 exploitation | 目标明确，容忍差实验少 | ξ（改进阈值） |
| PI（Probability of Improvement） | 强 exploitation | 有明确的当前 best | ξ |
| Thompson Sampling | 随机化 exploration | 并行实验场景 | 无 |

每种 AF 下附一句直觉解释（非数学语言）。

**§ Exploration vs. Exploitation**

内容：
- 两臂赌博机类比（2–3 段文字说明，配一张简单的示意图）
- 为什么纯 exploitation 会陷入局部最优
- 为什么纯 exploration 浪费了先验信息
- UCB 如何用 β 参数平衡两者

**§ Noise 影响**

内容：
- 什么是同方差噪声（homoscedastic）vs. 异方差噪声（heteroscedastic）
- 噪声如何影响 surrogate 的置信带（示意图）
- 实验噪声高时应该如何调整策略（增大重复次数 / 换更鲁棒的 AF）

### 2.7 Design Studio `/design-studio`（Phase B）

**目标**：将研究问题结构化为 SDL 设计草案。**此模块不在 Lecture MVP 范围内。**

**实现策略**：

- Phase B 第一版：离线模板策略
  - 用户填写输入表单（研究领域、目标属性、可控变量列举）
  - 前端基于用户输入生成固定格式的 8 字段输出（规则引擎，不调用 AI）
  - 生成的草案可在页面内直接编辑和下载

- Phase B 第二版（可选）：AI 增强
  - 在规则生成的基础上，可选择"用 AI 补充细节"（调用 Anthropic API）
  - AI 调用失败时，优雅降级到规则生成的版本，不影响核心功能
  - AI 调用必须对用户可见（显示"AI 正在生成补充建议..."提示）

**必须有的固定输出模板（8 字段）**：

```markdown
## SDL 设计草案

**Objective**
```

### 2.8 Resources `/resources`

**目标**：提供结构化、可按需查阅的资源体系，不是无序链接堆砌。

**内容结构**：

1. **阅读路径**（推荐顺序，分层）：
   - 入门必读（≤3 篇）：Szymanski 2023、Häse 2019、Griffiths 2020
   - 方法深入（≤5 篇）：按 DOE / BO / 多目标方向分类
   - 扩展阅读：按应用领域分类（合成化学 / 材料发现 / 过程优化）

   - BoFire：通用贝叶斯优化框架，适合材料发现
   - Ax / BoTorch：Meta 的 BO 平台，工业级
   - pyDOE2：传统 DOE 设计工具

3. **Benchmark 清单**（标注是否有开放数据集）：
   - 颜色匹配（RGB LED，开放数据）
   - SnAr 反应优化（Reizman & Jensen 2016，开放数据）
   - 青霉素批次优化（Goldrick et al. 2019，开放数据）
   - Perovskite 太阳能电池（Häse et al. 2019，开放数据）

4. **术语表**（可搜索，每个术语 1–3 句定义，不需要学术定义，需要直觉定义）

5. **MSE 实验目录入口**（链接到 Foundations 中的实验图谱矩阵）

## 3. 讲者模式完整规格

### 3.1 激活方式

- 方式 1：URL 参数 `?mode=lecture`（分享链接给讲者）
- 方式 2：全局导航右上角"讲者模式"按钮（需要 localStorage 记录偏好）

激活后：
- 顶部导航栏上方追加一行讲者工具栏（不替换，不遮挡原导航）
- 工具栏背景：琥珀色 `#B7791F`，文字白色
- 当前处于非讲座节点的页面（如 `/resources`）：工具栏仍显示，但"下一步"指向最近的讲座节点

### 3.2 讲者工具栏规格

```
[←] [节点 N/12: 节点名称] [→]   [Reset]  [Replay]  [退出讲者模式]
```

- `←` / `→`：切换讲座节点（同时更新页面路由和页面内的 scroll 位置）
- 节点名称：显示当前节点的人类可读名称（见 PRD §6.1 节点定义表）
- `Reset`：仅在 Case Studio 页面显示为可点击状态
- `Replay`：仅在 Case Studio 页面显示为可点击状态
- `退出讲者模式`：回到学生视图，保留当前页面位置

### 3.3 键盘快捷键（讲者模式下全局有效）

| 键 | 功能 |
|---|---|
| `→` 或 `Space` | 进入下一讲座节点 |
| `←` | 返回上一讲座节点 |
| `R` | Reset 当前 Case Studio 状态 |
| `P` | Replay（从第 1 步开始） |
| `F` | 全屏当前内容区域（不含工具栏） |
| `Esc` | 退出全屏或退出讲者模式（二次确认） |

## 5. 视觉设计规范

### 5.1 排版系统

**字体层级**：

| 用途 | 字体类型 | 字体建议 | 字重 | 字号 |
|---|---|---|---|---|
| 页面主标题（H1） | 衬线 | EB Garamond、Lora、Source Serif 4 | 700 | 36–48px |
| 章节标题（H2） | 衬线 | 同上 | 600 | 24–30px |
| 子节标题（H3） | 无衬线 | Source Sans Pro、Outfit | 600 | 18–20px |
| 正文段落 | 无衬线 | Source Sans Pro、Outfit | 400 | 16px |
| 数据与代码 | 等宽 | JetBrains Mono、Fira Code | 400 | 14px |
| 图注与标注 | 无衬线 | 同正文 | 500 | 13px |

**阅读舒适性约束**：
- 正文最大宽度：680px（约 68 字符/行）
- 行高：1.75
- 段落间距：24px
- 不使用纯白底色（`#FFFFFF`），使用暖白 `#FAFAF8`

### 5.2 颜色系统

**基础色**：

| 用途 | 颜色名 | 色值 |
|---|---|---|
| 页面背景 | 暖白 | `#FAFAF8` |
| 主文字 | 近黑 | `#1C1C1C` |
| 次级文字 | 中灰 | `#5A5552` |
| 辅助文字/标注 | 浅灰 | `#9B9590` |
| 边框/分隔线 | 半透明灰 | `rgba(28,24,20,0.10)` |
| 悬停背景 | 半透明暖灰 | `rgba(28,24,20,0.05)` |

**语义色（全站统一，不得在不同图表中使用相同颜色代表不同含义）**：

| 语义 | 颜色名 | 色值 | 用途 |
|---|---|---|---|
| 已探索实验点 | 中性灰 | `#9B9B9B` | Case Studio 散点、历史表 |
| 推荐下一实验点 | 学术蓝 | `#2B6CB0` | 散点图高亮、推荐区域 |
| 历史最优点 | 森林绿 | `#276749` | 散点图标注、best-so-far |
| 不确定性填充 | 暖琥珀（半透明）| `rgba(214,158,46,0.25)` | Surrogate 置信带 |
| 约束违反区域 | 砖红（半透明） | `rgba(197,48,48,0.15)` | 参数空间失败区域 |
| 讲者模式工具栏 | 琥珀 | `#B7791F` | 顶部工具栏背景 |
| 重要警告 | 砖红 | `#C53030` | 警告框边框 |

**禁止使用的颜色模式**：
- 随机彩虹色图表（不同系列用不同颜色但无语义关联）
- 纯白背景（`#FFFFFF`）
- 电光蓝、荧光绿等高饱和度"科技感"色彩

### 5.3 数据可视化规范

以下规范适用于所有图表（Case Studio、Foundations、Methods 中的所有图表）：

1. **轴标签必须带单位**：写"温度 (°C)"，不写"温度"；写"产率 (%)"，不写"产率"
2. **图例必须说明颜色语义**：不依赖颜色顺序，每种颜色配文字标签
3. **Hover 提示必须显示精确数值**：格式 `参数A = X [单位] | 参数B = Y [单位] | 观测值 = Z ± σ [单位]`
4. **点大小有语义时必须有图例说明**（否则所有点使用统一大小）
5. **禁止使用 3D 图表**
6. **图表宽度与容器同宽，高度固定（桌面端高度固定为容器高度的 60%）**
7. **所有图表下方必须有 1–2 句文字说明图表的意义**（不依赖标题传达全部信息）

### 5.4 组件级美学规范

**Case Studio 组件**（"实验室记录本"风格）：
- 历史记录表：等宽字体对齐数值列，无斑马纹（用细分隔线代替）
- 参数显示：`参数名 = 值 [单位]`，等宽字体
- 推荐理由：左边框引用块样式（`border-left: 3px solid #2B6CB0; padding-left: 16px`）
- 不使用悬浮卡片或弹窗

**A-Lab 组件**（"研究案例报告"风格）：
- 关键数字：Pull Quote 格式（大字号引用块，带来源引用）
- 系统组成：有向图，不是图标列表
- 争议部分：正方/反方/综合判断三段式，视觉上有清晰的分隔

**Foundations 组件**（"可交互教科书"风格）：
- 长段落间用 `margin-bottom: 32px` 分隔
- 交互块用虚线边框区分，标注"可交互"标签，背景轻微着色
- 禁止弹窗，用页内展开（accordion）代替

**全局禁止组件**：
- Stock photo Hero 横幅
- 功能徽章（"New!"、"🔥 Hot"、"Beta"）
- 渐变背景
- 动画计数器
- 以 Modal 弹窗承载核心学习内容

### 6.2 案例切换时的状态管理

- 切换案例时，所有与当前案例相关的状态重置（实验历史、推荐点、可视化状态）
- Seed 实验点在任何 Reset 操作后恢复（不被清除）
- 讲者模式的 Replay 功能从 seed 状态开始逐步回放

### 6.3 Surrogate 计算策略（离线优先）

Lecture MVP 阶段：
- 使用预计算的网格数据（`surrogate_grid`）展示 surrogate 可视化
- 推荐点从预计算的 acquisition function 网格中读取
- 不在浏览器内实时计算 GP posterior

Phase B 可选升级：
- 使用 `gptools` 或 WebAssembly 编译的 GP 库在浏览器内实时更新 surrogate
- 前提：保留预计算网格作为 fallback

## 7. 离线与降级行为

### 7.1 必须离线可用的功能（Lecture MVP 硬性约束）

以下功能在无网络、无 API 情况下必须完全正常工作：

- Case Studio：P0 三个案例的全部功能（推荐、步进、Reset、Replay、可视化）
- Foundations 交互块 1（SDL 闭环步进演示）
- Foundations 交互块 2（Acquisition Function 探索器）
- A-Lab 页面（纯静态）
- Foundations 页面（纯静态，含 MSE 图谱）
- 讲者模式工具栏（纯前端状态，无 API 依赖）

### 7.2 允许在线才能工作的功能（Phase B 可选）

- Design Studio 的 AI 增强模式（调用 Anthropic API）
- 学生进度同步（如果引入后端）
- 实时 GP surrogate 计算（WebAssembly 方案不需要网络，但 API 调用版本需要）

### 7.3 降级行为规范

当 AI API 不可用时（超时或错误）：
- Design Studio 自动切换到规则生成模式，显示提示："AI 服务暂时不可用，已切换到模板生成模式"
- 不显示错误弹窗，不中断用户工作流
- 规则生成的输出必须与 AI 增强输出使用相同的 8 字段模板格式
