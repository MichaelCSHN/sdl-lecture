# SDL 讲座 App PRD

版本：v2.0  
日期：2026-06-04  
状态：重写版，替代旧 v1.3  
产品定位：研究生层级的 SDL 课程化交互学习应用，而不是一次性讲座网页

## 1. 产品定义

### 1.1 一句话定义

围绕 Self-driving Labs（SDL）与 A-Lab，构建一个面向材料、化学、实验科学研究生的“在线课程式”学习应用：既能承载讲座现场演示，也能在课后独立学习、反复操作、复盘实验策略。

### 1.2 为什么要重写

旧版本 PRD 和当前实现共同存在两个根本问题：

1. 产品形态过于接近“长页面讲座稿”，不像课程产品。
2. SDL case 区域过于 toy / naive，缺乏研究生课程需要的实验语境、代理模型语境、测量语境和决策语境。

### 1.3 新版本的核心判断

这不是“把 PPT 换成网页”。

这应该是一个具备以下特征的课程产品：

1. 有课程结构，而不是只有内容分段。
2. 有实验语义，而不是只有图表交互。
3. 有案例深度，而不是只有函数优化。
4. 有学习闭环，而不是只有浏览闭环。
5. 有研究生可接受的科学严谨度，而不是面向大众科普的轻量演示。

## 2. 产品目标

### 2.1 主目标

1. 让学生建立对 SDL 的完整心智模型：问题定义、实验闭环、DOE、BO、代理模型、自动化、验证与局限。
2. 让学生通过高质量交互案例理解“为什么 SDL 有效”，而不是只记住几个术语。
3. 让讲者在现场能够稳定演示关键概念、关键案例和关键 trade-off。
4. 让课后访问者能够按课程路径独立学习，形成可复用教学资产。

### 2.2 非目标

1. 不追求直接控制真实硬件。
2. 不追求做成通用 ELN/LIMS。
3. 不追求在首版覆盖全部 SDL 方向。
4. 不追求把所有论文信息塞进一个页面。

## 3. 目标用户

### 3.1 主要用户

1. 材料、化学、实验科学相关方向研究生。
2. 对 BO / DOE / 自动化实验有兴趣的科研人员。
3. 讲课教师与课程助教。

### 3.2 用户水平假设

1. 看得懂实验参数、目标函数、误差和约束。
2. 不要求用户已有 Bayesian Optimization 实战经验。
3. 默认用户能接受中英混合术语和论文级图示。

## 4. 使用场景

### 4.1 现场讲座模式

1. 讲者按课程目录推进内容。
2. 在关键位置打开案例工作台现场演示。
3. 可切换“讲者模式”，快速重置案例、快进实验轮次、突出关键图层。

### 4.2 课后学习模式

1. 学生按章节学习。
2. 每章有目标、重点、术语、交互、检查点。
3. 可以保存自己的实验历史、理解笔记和完成进度。

### 4.3 研究启发模式

1. 学生输入自己的课题。
2. 系统输出 SDL 化拆解建议。
3. 系统明确指出“适合 SDL 的部分”和“不适合自动化的部分”。

## 5. 成功标准

### 5.1 教学结果

1. 学生能清楚区分 DOE、surrogate model、acquisition function、measurement、validation。
2. 学生能解释至少一个 SDL case 中“为什么下一次实验是这个点”。
3. 学生能识别 SDL 的边界条件，而不是把它神化为万能工具。

### 5.2 产品结果

1. 课程结构完整，可独立使用，不依赖讲者口头补充才能理解。
2. 至少 3 个高质量案例达到“研究生可讲”的标准。
3. 讲座现场主链路不依赖外部 API 成功返回。
4. 课后用户可以在 20 分钟内完成一条完整学习路径。

## 6. 产品原则

1. 课程优先：优先按学习路径组织，而不是按炫技组件组织。
2. 实验优先：所有交互都要落到实验变量、观测值、决策逻辑上。
3. 证据优先：A-Lab 相关内容必须有来源、限制和争议说明。
4. 渐进复杂：先讲 intuition，再讲 formalism，再讲 case。
5. 可复盘：任何 case 都必须能回看实验历史和推荐理由。

## 7. 信息架构

首版采用“课程站点 + 案例工作台”的双层结构，而不是单页长滚动。

### 7.1 一级结构

1. 首页 `/`
2. 课程导览 `/course`
3. Foundations `/foundations`
4. A-Lab Case File `/a-lab`
5. Case Studio `/case-studio`
6. Methods Lab `/methods`
7. Research Design Studio `/design-studio`
8. Resources `/resources`

### 7.2 导航原则

1. 顶部为全局导航。
2. 左侧为课程目录。
3. 右侧或底部为当前章节的术语、下载、延伸阅读、进度。
4. Case Studio 独立成工作台，不埋在普通内容章节里。

## 8. 核心功能需求

## 8.1 首页

### 必须有

1. 清晰说明这是“课程型 SDL 学习应用”。
2. 展示课程目标、适合人群、预计时长、学习路径。
3. 提供“开始课程”“直接进入案例工作台”“查看 A-Lab 档案”三个入口。
4. 首页 hero 不允许继续使用 placeholder 视频。

### 应该有

1. 讲者信息与课程背景。
2. 一张课程地图图示。
3. 最近更新内容。

## 8.2 课程导览

### 必须有

1. 课程章节目录。
2. 每章学习目标。
3. 每章预计时间。
4. 每章 prerequisite / next step。

### 应该有

1. 完成进度。
2. 章节检查点。
3. 推荐阅读顺序。

## 8.3 Foundations

这是“知识基础课”，不只是背景知识堆砌。

### 必须有

1. 什么是 SDL。
2. 为什么传统实验优化慢。
3. DOE 基础。
4. BO 基础。
5. surrogate model / uncertainty / acquisition 的关系。
6. DMTA-L 闭环。
7. SDL 的失败模式与边界。

### 交互要求

1. 每个关键术语可展开。
2. 每个关键图必须能单独阅读，不依赖讲者口述。
3. 至少有 2 个“概念 -> 交互 -> 解释”闭环。

## 8.4 A-Lab Case File

这是课程的“深度案例档案页”，不是时间线加卡片。

### 必须有

1. A-Lab 做了什么问题。
2. 系统组成：规划、执行、表征、分析、闭环。
3. 为什么它重要。
4. 关键结果来自哪里。
5. 学界争议和再分析结论。
6. 哪些地方值得借鉴，哪些地方不能照搬。

### 展示要求

1. 论文级叙事结构：问题、方法、结果、验证、限制、启示。
2. 用“档案页”而不是“营销页”的写法。
3. 关键数字必须带来源。
4. 要明确写出验证标准、争议点和未解决问题。

## 8.5 Case Studio

这是本产品的核心，也是旧版本最薄弱的部分。

### 目标

让学生在接近真实实验优化语境的工作台中操作案例，而不是在抽象函数上“玩曲面”。

### 所有 case 的统一要求

每个 case 必须包含：

1. 问题背景。
2. 参数空间。
3. 目标指标。
4. 观测噪声 / 重复实验语义。
5. 约束条件。
6. 初始设计方案。
7. 代理模型状态。
8. acquisition function 可视化或解释。
9. 推荐下一实验点及理由。
10. 实验历史表。
11. best-so-far 曲线。
12. reset / replay / seed 固定。

### 案例分层

#### P0 基准案例

1. RGB LED / 色彩匹配案例。
2. SnAr 或 Suzuki 反应优化案例。
3. 钙钛矿或电解液配方优化案例。

#### P1 进阶案例

1. 多目标绿色化学案例。
2. A-Lab 风格无机材料筛选案例。

#### P2 拓展案例

1. 数字孪生 PDE / 相场案例。
2. 基于预训练模型的材料成分搜索案例。

### 关键 benchmark 要求

`self-driving-lab-demo` 提供的不是“更华丽的 UI”，而是更正确的案例组织方式。新版本必须吸收以下特征：

1. 案例对应明确的物理/化学任务，而不是抽象数学任务。
2. 案例有“测量”语义，而不是只显示目标函数值。
3. 案例有实验循环，而不是只有参数滑块。
4. 案例是可复现的、可讲解的、可扩展的。
5. 案例具有教学价值：能解释 closed-loop decision making。

## 8.6 Methods Lab

这是“方法实验室”，用来系统讲透 DOE 与 BO，而不只是附属图表。

### 必须有

1. DOE 方法对比：Random / LHS / Sobol / Full Factorial。
2. BO 对比：EI / UCB / PI。
3. exploration vs exploitation 的交互展示。
4. noise 对策略的影响。
5. batch size 对策略的影响。
6. 多目标优化的 Pareto 基础。

### 应该有

1. 初始点数量敏感性分析。
2. kernel length scale 对 posterior 的影响。
3. 不同 surrogate family 的差异简介。

## 8.7 Research Design Studio

### 必须有

1. 用户输入自己的课题。
2. 系统输出“问题定义 -> 参数 -> 约束 -> 可测指标 -> 合适策略 -> 风险”结构化结果。
3. 结果必须有固定模板，不允许只输出一段聊天文字。
4. 必须支持离线 fallback。

### 应该有

1. 区分“适合 SDL”“部分适合”“当前不适合”。
2. 给出最小可行 SDL 化建议。

## 8.8 Resources

### 必须有

1. 阅读路径，而不是纯链接堆。
2. 论文分类：入门综述、关键系统、案例、方法、争议。
3. 工具分类：BayBE、Olympus、Ax/BoTorch、Honegumi、Materials Project。
4. 术语表。

### 应该有

1. 章节后的推荐阅读。
2. BibTeX 下载。
3. 常见问题。

## 9. 内容质量标准

### 9.1 研究生层级标准

任何页面内容都不能只停留在：

1. 名词解释。
2. 一句结论。
3. 静态数字展示。

必须尽量回答：

1. 这个问题是什么。
2. 变量是什么。
3. 为什么这个策略合理。
4. 数据从哪里来。
5. 不确定性在哪里。
6. 什么地方会失败。

### 9.2 A-Lab 内容标准

1. 必须区分“论文原始结论”和“后来评论/再分析”。
2. 必须标注来源。
3. 不允许把未证实说法包装成定论。

### 9.3 Case 内容标准

1. 至少半数 case 必须是 literature-grounded 或 benchmark-grounded。
2. 不允许用多个换皮高斯峰函数冒充不同科研场景。
3. 如果是 toy case，必须明确标注“概念教学用”。

## 10. 技术与实现要求

### 10.1 架构要求

1. 从单页讲座站点升级为 route-based 应用。
2. 内容层与案例层分离。
3. case 采用统一接口抽象。
4. 课程内容可独立维护，不与实验逻辑混杂。

### 10.2 Case Engine 抽象

每个 case 至少定义：

1. metadata
2. parameter schema
3. constraints
4. simulator / evaluator
5. observation model
6. initial design generator
7. recommender hook
8. visualization adapters

### 10.3 可靠性

1. 核心演示链路不依赖在线 API。
2. LLM 失败时仍能完成课程。
3. 所有关键 case 支持 deterministic seed。

## 11. 非功能需求

1. 首屏进入核心内容不超过 3 秒。
2. 讲者模式下重置 case 不超过 1 秒。
3. 所有主要页面适配桌面与移动端。
4. 所有关键图表有文字说明。
5. 讲座现场支持离线或弱网演示。

## 12. 分期

### 12.1 Phase 1：课程骨架重构

1. 路由与课程结构。
2. 首页、课程导览、Foundations、A-Lab 档案页初版。
3. Case Studio 工作台骨架。

### 12.2 Phase 2：高质量案例

1. RGB LED benchmark case。
2. SnAr / Suzuki case。
3. Perovskite / Battery case。
4. Methods Lab 完整化。

### 12.3 Phase 3：研究工作流增强

1. Research Design Studio 结构化输出。
2. 课程进度、笔记、导出。
3. 资源体系和作业式检查点。

## 13. 版本验收定义

### 必须同时满足

1. 用户可以按课程顺序学习，而不是只能滚动浏览。
2. 至少 3 个 case 达到研究生课堂可讲标准。
3. A-Lab 页面具备“问题-方法-结果-争议-启示”完整结构。
4. Methods Lab 能清楚演示 DOE 与 BO 的差异。
5. Research Design Studio 输出结构化建议，而不是泛泛对话。

## 14. 对当前项目的明确结论

当前项目不是失败的 demo，但它还不是这个 PRD 定义下的产品。

它更接近：

1. 讲座型单页应用。
2. 概念演示站点。
3. 带若干教学 toy case 的可视化原型。

它还不是：

1. 课程化学习应用。
2. 研究生层级 SDL 案例平台。
3. 可严肃支撑“SDL case 教学”的主产品。

## 15. 外部 benchmark

重点参考：

1. `sparks-baird/self-driving-lab-demo`
2. BayBE
3. Olympus
4. Honegumi
5. A-Lab 与相关评论/再分析材料

本产品不要求复制这些系统，但必须吸收其“案例组织、实验语义、闭环逻辑、可复现性”的优点。
