# SDL Course App Project Charter

状态：active  
日期：2026-06-04  
角色：CTO 基线文档

## 1. 项目重启结论

本项目不再沿用“SDL 讲座单页网页”的产品定义。即日起，项目目标改为一门完整课程的数字课程平台：

1. `North Star`：完整在线课程。
2. `Immediate Milestone`：一次 3 小时研究生讲座版 MVP。

讲座版不再被视为独立产品阶段，而是完整课程的一条精选路径。

当前仓库代码视为 `legacy prototype`。它不是废物，但也不再作为产品结构的依据。是否复用，服从新规格，而不是服从旧页面结构。

## 2. 业务目标

### 完整课程目标

1. 建立面向研究生和高年级本科生的课程结构。
2. 覆盖 MSE 中的实验、传统实验方法论、AI 时代的 SDL。
3. 建立课程目录、章节目标、检查点、案例工作台和研究设计工作室。
4. 允许后续接入更多 benchmark、作业和阅读路径。

### 讲座压缩版目标

1. 支撑一场 3 小时研究生讲座的完整叙事。
2. 至少提供 2 个研究生层级可讲的 SDL 案例，其中 1 个必须可在现场稳定演示。
3. 将 A-Lab 讲清楚到“问题、系统、结果、争议、启示”五段式，而不是时间线式展板。
4. 让学生在课后 20 到 30 分钟内完成一次独立浏览和一次最小案例复盘。

## 2.1 当前交付优先级

当前策略不是“讲座优先定义产品”，而是：

1. 用完整课程定义产品上限。
2. 用讲座 deadline 决定当前交付顺序。

因此近期执行顺序为：

1. 先交付讲座版 MVP。
2. 讲座版必须直接复用课程平台骨架。
3. 讲座结束后继续补齐完整课程能力。

## 3. 产品判断

当前实现的主要问题不是“UI 不够漂亮”，而是：

1. 产品形态错了。它是单页讲座 demo，不是课程产品。
2. 案例语义弱了。它更像函数优化演示，不像实验优化。
3. 内容组织浅了。它更像知识展板，不像研究生课程。

因此，项目重启采用“先顶层文档，后重构执行”的方式，不直接在旧页面上继续堆内容。

## 4. 范围边界

### 本阶段纳入

1. 课程级信息架构。
2. 完整课程与讲座压缩版共用的内容骨架。
3. Background / Foundations 核心单元。
4. A-Lab 深度案例页。
5. Case Studio 与 case engine。
6. 至少 2 个高质量案例。

### 本阶段不纳入

1. 真实硬件控制。
2. 通用 ELN/LIMS。
3. 大规模用户系统。
4. 需要 CUDA 才能运行的本地大模型依赖。

## 5. 技术路线总决策

1. 继续使用当前前端栈做第一阶段重构：`React + TypeScript + Vite`。
2. 当前阶段默认在 Windows 本地开发，不强制切到 WSL。
3. 仅当出现以下需求时再切 WSL 或 AutoDL：
   - Linux 专属依赖明显更稳
   - 需要长期跑 Python 数据处理或模型服务
   - 需要与远端 GPU 环境联动
4. Python/Node 开发基线统一收敛到一个 `conda` 环境，避免本机全局版本漂移。

## 6. 协作模型

1. 我负责 CTO 工作：目标定义、规格把控、阶段拆解、验收标准、代码审查。
2. 本地 Claude Code 负责执行开发、提交报告、按阶段交付。
3. 用户负责关键方向确认、资源提供、最终验收。

详细流程见 [04_Operating_Model.md](/D:/A-Lab/sdl-lecture/docs/04_Operating_Model.md)。

## 7. 第一阶段输出物

1. PRD

3. Technical spec

5. Claude Code 首轮任务书

## 8. 当前策略：保留还是删除旧代码

结论：暂不立即删除，先标记为 `legacy prototype`。

理由：

1. 其中有可复用的数据、图表和局部组件。
2. 但整体页面结构不值得延续。
3. 在新路由、新内容模型和新 case engine 定下来之前，先不要做情绪化清空。

后续如果 Claude 在 Phase 1 重构中发现旧结构阻力太大，可以进行选择性删除或直接绿地重建。
