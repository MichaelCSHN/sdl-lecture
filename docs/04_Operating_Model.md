# SDL Course App Operating Model

版本：1.0  
日期：2026-06-04  
状态：active

## 1. 角色分工

### CTO

负责：

1. 目标与边界
2. 顶层文档
3. 阶段拆解
4. 审查验收
5. 风险判断

### Claude Code

负责：

1. 代码实现
2. 本地测试
3. 阶段性提交
4. 交付报告

### 用户

负责：

1. 方向确认
2. 资源提供
3. 最终验收

## 2. 执行原则

1. Claude 先执行，我后审查。
2. 先小阶段交付，再推进下一阶段。
3. 所有开发都必须对齐 PRD 与 spec，而不是对齐旧页面。

## 3. 提交流程

1. Claude 每完成一个清晰阶段就 commit 一次。
2. 每次提交后都要给出：
   - commit SHA
   - 修改范围
   - 构建结果
   - 已完成项
   - 未完成项
3. 我按提交进行审查。

## 4. 验收门

进入下一阶段前，至少满足：

1. 构建通过
2. 当前阶段验收项可演示
3. 代码结构没有明显倒退
4. 文档与实现没有脱节

## 5. 环境策略

1. 当前阶段优先用 Windows 本地。
2. 如需 Python 辅助或数据处理，统一进 `conda` 环境。
3. 如未来需要 Linux-only 工具链、远程 GPU 或大模型服务，再切 WSL 或 AutoDL。

## 6. 当前建议

项目现在适合的流程是：

1. 我维护规格和任务书。
2. Claude 执行单个阶段。
3. 我审查后决定：
   - 合并推进
   - 要求返工
   - 改变优先级
